# 求职工作台

本地运行的求职全流程工具：**岗位库 → JD匹配分析 → AI智能改简历 → 信息库**。数据全部存本机（SQLite），不上传第三方。

> 👉 想先看「能干什么、能自定义什么、现在有哪些坑」：**[功能介绍 FEATURES.md](FEATURES.md)**（含快速上手、平台现状、已知 bug 清单）

## 分析功能自测与样例数据

- `npm run test:analysis`：离线自测分析引擎（输入校验、证据规则、ID 关联、评分公式、基础模式降级），不需要 AI Key
- `npm run seed:sample-analysis`：生成一份**明确标注「样例数据」**的分析记录（结构与真实 AI 分析一致），用于演示要求对照、表达缺口、采纳/撤销、生成简历等状态
- `node scripts/ui-check.mjs`：无头 Chrome 检查页面渲染、四种分析状态与移动端布局，输出 `data/ui-check.png` 截图
- 样例数据（简历、经历库、岗位、分析）均以「【样例】」或「样例数据」命名/标注，正式使用前可在信息库与岗位库中删除

## 配置 AI Key（三种方式，任选其一）

支持任意 **OpenAI 兼容**接口（智谱 / Z.AI / DeepSeek / 通义 / Kimi / OpenAI / 本地 Ollama…）。

**方式 1：界面配置（最快）**
打开「设置 → AI 服务」填写 API Base、模型名、API Key → 保存 → 点「测试连接」。Key 保存在本地 `data/workbench.db`，不会上传。

**方式 2：环境变量（推荐用于部署/容器）**
环境变量优先级高于界面配置，Key 不落库：

```bash
AI_API_KEY=sk-xxx \
AI_API_BASE=https://api.deepseek.com \
AI_MODEL=deepseek-flash \
PORT=8787 node server.js
```

> DeepSeek 官方模型 ID：`deepseek-flash`（即 DeepSeek-V4.1-Flash-1017）、`deepseek-v4-pro`。旧的 `deepseek-chat` / `deepseek-reasoner` 已于 2026-07-24 弃用；`deepseek-4.1flash` 不是有效模型名。

**方式 3：`.env` 文件（本地常驻）**

```bash
cp .env.example .env    # 填好 Key/Base/Model
npm start               # 启动时自动读取 .env（已存在的环境变量优先）
```

`.env` 已加入 `.gitignore`，不会被提交。配置生效后设置页会显示「环境变量」标记且 Key 输入框禁用；修改环境变量需重启服务。

填好 Key 后运行自检（会验证 Key、模型名与 JSON 输出模式）：

```bash
npm run ai:check
```
模型需支持 `response_format: json_object`（主流 OpenAI 兼容服务均支持）；若模型不支持 JSON 模式，分析会返回明确的失败状态而不是假结论。

```bash
cd job-workbench
```

## 四大功能

### 1️⃣ 岗位库
- **筛选**：岗位关键词（默认产品经理）、城市（默认深圳）、经验（社招3年内）、薪资下限（默认15K）、业务分类多选（AI/电商/用户产品/B端/硬件/物联网等，自动按标题/标签/JD归类）、最新发布在前
- **导入岗位（4种方式）**：
  - 📋 **粘贴JD**：在 Boss直聘/脉脉 岗位页全选复制，粘贴即自动解析字段（有 AI Key 时语义解析，否则规则解析）
  - 🤖 **采集结果**：一键导入 [boss-zhipin-scraper](https://github.com/eatmoreduck/boss-zhipin-scraper) 的输出（见下文）
  - 📦 **JSON/CSV**：其他采集工具导出文件，字段自动映射，按链接/公司+岗位去重
  - 🔗 **链接导入**：尽力抓取（多数招聘站有登录墙，失败就用粘贴）
- **收藏**（★）、**去投递**（打开Boss原岗位页并标记「待投递」，实际投递完成后点「✓ 确认已投递」——不会因为你没登录Boss就假装已投递）、投递状态跟踪（未处理/已打招呼/待投递/已投递/面试中/offer）
- **👋 一键打招呼**（在「去投递」旁边）：按「设置 → 打招呼」的模板（称呼/经验说法/一句话亮点）拼出文案 → 复制到剪贴板 → 打开原岗位页 → 你点「立即沟通」粘贴发送；发送后记录时间与文案、状态自动推进（不覆盖更靠后的进度）。文案只拼接你填的字段与岗位信息，不调用 AI、不编造经历；可在设置里改模板或开启「先预览/改文案再发送」

### 2️⃣ JD匹配分析（证据驱动）
- 输入分开：**目标岗位JD（可选1-5个）** + **当前投递简历（必选）** + **完整经历库（可选）** + **用户补充回答（可选）**
- 分析前先做输入质量校验：JD 只有职位名称、缺职责/要求、混入推荐职位等页面噪声，或简历过短时会明确指出，**不输出虚假评分**
- 投递概览：**推荐投递 / 调整后投递 / 探索投递 / 暂不优先 / 信息不足** + 一句话理由 + 最多3项有证据的优势 + 最多3项风险 + 未确认事项 + 可信度及原因
- JD 要求逐条拆解（硬性条件/核心职责/专业能力/行业经验/加分项），每条给出：JD原文与位置、优先级及依据（原文/推断）、判断（直接匹配/可迁移/待确认/明确不满足）、经历证据原文与来源、简历是否已体现、判断理由、差距类型（表达缺口/证据不足/可迁移经验/能力缺口/硬性条件差距）、下一步
- **区分「经历库有但简历没写」（表达缺口）与「材料没证据」（待确认）**；不会因为简历没写就判定你不会
- 简历修改：按影响排序，top3 可展开全部；每项含对应要求、原文、建议改写、依据、待确认信息、修改类型；支持复制 / 采纳 / 编辑后采纳 / 撤销
- 能力补齐：按「投递前 / 面试前 / 长期」分组，含目标深度、知识点、实践任务、预计投入（估计）、可检查产出与验收标准
- 待补充信息：最多 5 个高影响问题，回答后重新分析并标出被更新的判断
- **材料匹配参考分**：代码按固定公式计算（直接匹配1、可迁移0.6、明确不满足0、待确认不计入；硬性条件30%/核心职责25%/专业能力25%/行业经验10%/加分项10%），展示维度分、权重、证据覆盖与未知项；未知项≥60% 或要求少于3条不展示总分；硬性条件差距单独提示。该分数**不代表面试率或录用率**
- 多选岗位时额外提炼**跨岗位共性要求**，并给出逐岗投递建议
- **多岗位并发 + 实时进度**：默认 2 个岗位并发分析，顶部显示进度条与百分比，并逐步回显「第几个/共几个、哪个岗位已完成、已用多少秒」，不再是一个静态 loading（2 个岗位实测约 1 分钟）
- **分析参数可调**（设置 → 分析参数）：思考强度（低/关闭）、多岗位并发数（1-3）、单岗最大输出 token、单岗超时；出现输出被截断或 `finish_reason=length` 时可提高输出上限或关闭思考
- 无 AI Key / 模型失败时：明确标注**基础文本检查**（只做 JD 句子切分与词语覆盖），不生成语义匹配、能力判断或模板化改写；失败时可重试
- 历史分析可回看；JD 或简历在分析后被修改会提示「结果可能过期」

### 3️⃣ AI智能改简历
- 承接分析页选中的岗位：单选=针对性改写，多选=按共性要求改写
- 以面试官视角重排与润色（严格基于真实经历，不编造），输出 Markdown 简历 + 逐条改动说明
- **手动编辑**：双栏对照（编辑/预览），保存、复制全文、下载 .md、打印成 PDF、版本历史

### 4️⃣ 信息库
- 上传文件（PDF/DOCX/TXT/MD ≤20MB）、粘贴文本、在线链接抓取
- **上传先预览再入库**：显示实际提取到的字数、页数、解析方式（PDF 文字层 / 系统 OCR / Word），全文可直接编辑后再保存——避免把「只有抬头几十个字」的简历当完整材料用
- **解析不足自动 OCR**：PDF 正文是图片、或字体提取不到时（设计类简历常见），会用 macOS 自带 Vision 本地 OCR 重新识别（中英双语，最多 15 页，不上传文件）；仍不理想可一键重试 OCR 或改用粘贴文本
- 解析可能不完整的资料会在列表打标签，分析页选中它时也会明确提示
- 资料分类（简历/项目文档/工作成果/笔记），供分析与改简历引用

## AI 配置（推荐）

「设置」页配置任意 OpenAI 兼容接口：智谱 / Z.AI / DeepSeek / OpenAI / 本地 Ollama。配置后解锁：JD 语义解析、深度匹配分析、共性提炼、AI 改简历。未配置时为**简易模式**（关键词级匹配，功能可体验但深度有限）。

## 对接 boss-zhipin-scraper 采集 Boss直聘 JD

> 克隆本仓库后，需先把采集器克隆到 `collector/` 目录（本仓库不含第三方采集器代码）：
> ```bash
> mkdir -p collector && git clone --depth 1 https://github.com/eatmoreduck/boss-zhipin-scraper.git collector/boss-zhipin-scraper
> pip3 install -r collector/boss-zhipin-scraper/requirements.txt
> ```

工作台已内置对接（依赖装好后）：

```bash
# ① 首次：创建专用Chrome并登录你的Boss账号（仅一次）
cd collector/boss-zhipin-scraper
python3 scripts/boss_cdp_raw.py --setup-chrome

# ② 采集：深圳·产品经理·1-3年·本科（也可用 npm run collect）
python3 scripts/boss_cdp_raw.py --city 深圳 --keyword 产品经理 --experience 104 --degree 203
# 经验码: 101不限 103<1年 104=1-3年 105=3-5年 106=5-10年；学历码: 202大专 203本科 204硕士

# ③ 回工作台「导入岗位→采集结果」一键入库（自动合并JD详情、按job_id去重）
```

### ⏰ 每日定时采集（默认每天 9:00）

「设置」页可配置定时采集：**每天 9:00 自动运行采集器**（默认深圳·产品经理·1-3年·本科），抓取最新岗位与JD详情，完成后自动导入岗位库、并补齐库内缺失的JD正文。

- 服务在运行才会触发；当天 9 点未运行的话，**服务启动后会自动补跑当天任务**
- 首页一次 `--setup-chrome` 登录后即可无人值守；登录态过期任务会失败并在状态里提示重新登录
- 也可点「立即运行一次」手动触发；运行日志：`data/scheduler.log`
- **「立即运行」= 全量采集**：抓列表 + 每个岗位的 JD 详情（一条 JD = 基础数据 + 详情），设置页每 3 秒刷新「已完成 X/Y 条 JD」与进度条；「定时采集的详情数量」填 0 表示全部（默认），手动运行不受该限制
- 采集器输出实时写入 `data/scheduler.log`；总时长上限 90 分钟，连续 10 分钟无输出会被判定卡死并终止，失败原因直接显示在设置页
- 可修改采集时间/城市/关键词/经验/学历/页数，也可随时停用

原理：Chrome CDP 复用你本人登录态，被动捕获页面自身 API 响应，输出至 `~/.boss-zhipin-scraper/job-result/`。

**风险与边界**：采集仅供个人求职研究，请控制频率，自行评估平台条款合规性，勿商用转售。脉脉无成熟采集器，用「粘贴JD」导入。真实批量投递可配合 [Ocyss/boss-helper](https://github.com/Ocyss/boss-helper) 浏览器插件；本工作台的「一键投递」做状态登记+跳转。

## 技术栈与结构

- 后端：Node 22（内置 SQLite，零原生依赖）+ Express
- 前端：React 18 + Vite，构建产物由后端静态服务
- `server.js` API与静态服务 ｜ `db.js` 数据层 ｜ `ai.js` AI提示词与调用+简易模式 ｜ `seed.js` 示例数据
- 数据目录：`data/workbench.db`（岗位/资料/分析/简历版本/设置全在里面，删库重置）
